Let agents edit Office files without handing them the file.

Your agent reads bounded parts of a Word, Excel, PowerPoint or PDF file and proposes a change set. Your application reviews it, commits it against the exact version it was planned on, and verifies the written file. The model never writes bytes and never approves its own change.

Read the agent quickstart View on GitHub

Model-neutral TypeScript. Works with any tool-calling model, or with no model at all.

Why not let the model write the file?

An Office file is a package of XML parts, relationships and styles. A model that regenerates it loses whatever it did not read.

  • The original bytes stay in charge.Engines patch only the parts a change touches. Everything else in the package is left byte-for-byte as it was.
  • Operations are typed.The model chooses from the operations this particular file supports, each with a JSON input schema, instead of free-form edits.
  • Reads are bounded.Capability schemas and bounded reads, with item and byte budgets, replace dumping whole archives into a prompt.

The change-set lifecycle.

Every tool is plain JSON. Only two of them ever write, and both belong to your application.

ToolWhat it doesWrites the file?
office.capabilitiesLists the operations this file supports and their input schemasNo
office.inspect, office.readReturns bounded structure and content at the current revisionNo
office.planKeeps an immutable change set bound to the file's revision and fingerprintNo
office.validateChecks the plan against core and format rulesNo
office.preview, office.diffShows the proposed result and the exact changesNo
office.verifyChecks the planned resultNo
office.commitApplies the change set only if the file has not changed, then verifies the written fileYes
office.restoreRestores a host version, when the adapter supports itYes

The model proposes. Your application approves.

An agent's proposal is untrusted input. InjOffice gives you revision checks and bounded operations; who may change which file stays your decision.

  • Bind approval to the exact plan: the reviewer, the file, its revision and the complete change set. It expires when any of them changes.
  • Never take approval from model output. Keep commit and restore out of the tools the model can call.
  • Commit with an idempotency key, so a retry of one logical change cannot apply twice.
  • Authorize every write in your application. Adapter confirmation flags add a guard; they are not access control.
Refused
The plan cannot be applied as asked. Keep the original and show the issues.
Stale revision
The file changed after review. Re-read, re-plan and ask again.
Committed and verified
The replacement was written and the checks passed.
Written, not verified
A replacement exists but failed its checks. Withhold the download and keep the evidence.

Wire it to any tool-calling model.

The dispatcher speaks one JSON envelope. Each tool descriptor carries a name, a description and a JSON input schema, so it maps onto any provider's tool format.

import {
  AGENT_TOOLS_PROTOCOL, AGENT_TOOLS_PROTOCOL_VERSION,
  createAgentToolDispatcher,
} from '@injoffice/agent-tools'

const dispatcher = createAgentToolDispatcher(session)

// The model may read and propose. Commit and restore
// stay with your review step.
const modelTools = dispatcher.descriptors.filter(
  (tool) => !['office.commit', 'office.restore']
    .includes(tool.name),
)

async function onToolCall(call) {
  if (!modelTools.some((t) => t.name === call.name)) {
    throw new Error('Not a model tool')
  }
  return dispatcher.dispatch({
    protocol: AGENT_TOOLS_PROTOCOL,
    protocolVersion: AGENT_TOOLS_PROTOCOL_VERSION,
    requestId: call.id,
    method: call.name,
    params: call.arguments,
  })
}
  • Any transport. An HTTP route, an MCP server or a Worker bridge can carry these messages. The package does not install or authenticate a transport for you.
  • Any adapter. Sessions take a format adapter from @injoffice/agent-office, or your own implementation of the adapter interface.
  • No model required. A deterministic proposal exercises the same boundary, which is how the playground's guided agent tasks work.
